## Phase Goal

**As a** Colombo consumer, **I want to** search, filter, and browse the business directory entirely as a guest, signing up via phone OTP only when I'm ready, **so that** I can quickly decide where to eat, shop, or hire a local service without friction or a forced login.

<objective>
Build the single shared search-ranking engine using Postgres native full-text search
(`tsvector`/GIN index + `pg_trgm` fallback), NOT a standalone OpenSearch/Elasticsearch
cluster (D-01: bootstrap-budget-appropriate at ~107 seeded businesses; the query layer
is structured so a future OpenSearch migration only swaps this module, not the data
model) — text relevance (tsvector), geo-decay, an honestly-neutral rating term (D-02),
category/price/attribute filter composition, all 4 sort options, and the open-now
application-layer post-filter — as one well-tested `lib/search/` module with zero UI or
route-handler code.

Purpose: This is the one place in the whole phase Prisma's query builder genuinely cannot reach (no `tsvector`/`ST_Distance` support), so it is deliberately isolated as a raw-SQL escape hatch shared by both the SSR search page (02-04) and its client-fetch API route (02-04/02-08) — duplicating this logic in two places would risk silent drift between them (RESEARCH.md's explicitly-called-out anti-pattern). Building it standalone, with its own integration tests against the real local Postgres instance, keeps this genuinely complex ranking math correct before any UI consumes it.
Output: `lib/search/run-search-query.ts` and its 3 supporting modules, proven correct via `run-search-query.test.ts` and `geo-decay.test.ts` against real seeded-shape fixtures.
</objective>
