## Phase Goal

**As a** Colombo consumer, **I want to** browse a real, structured directory of local
businesses — with categories, hours, address, attributes, and photos — **so that** I can
find and learn about a business before visiting or contacting it.

<objective>
Deliver LIST-03 (category-conditional attributes), LIST-04 (photo gallery + restaurant menu
tab), and LIST-05 (the full Sri Lanka-relevant category taxonomy) as one vertical slice on
top of the business page from 01-01/01-02.

Purpose: finalize the category taxonomy (needed by both the attribute-badge UI here and the
full 100-300-business seed dataset in 01-04) and prove category-conditional rendering works
correctly for at least one restaurant (Menu tab) and one non-restaurant (no Menu tab)
business.

Output: `category-config.ts` (taxonomy + Zod attribute schemas), `AttributeBadges` and
`PhotoGallery` components wired into the live business page.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer-curated `attributes` jsonb -> Postgres | Same seed-script write path, now validated per-category |
| Next.js Image Optimization -> external photo host (picsum.photos) | Next.js server-side-fetches and transforms remote images before serving them to the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `businesses.attributes` jsonb not matching its category's schema (unknown keys, wrong types silently coerced) | high | mitigate | Every `attributeSchemaByCategory[slug]` is `.strict()` (rejects unknown keys) and validated in the seed script before upsert, and `AttributeBadges` uses `safeParse` at render time as defense-in-depth against any data that bypassed seeding |
| T-03-02 | Tampering / Information Disclosure | Next.js Image Optimization fetching arbitrary remote URLs (SSRF-adjacent) if `images.remotePatterns` were left open | high | mitigate | `next.config.ts` restricts `images.remotePatterns` to exactly `picsum.photos`, not a wildcard — no code path in this phase accepts a user-supplied photo URL (that arrives in Phase 5's upload feature, which gets its own threat model then) |
| T-03-03 | Tampering | Menu tab rendered for a non-restaurant business by a category-matching bug | medium | mitigate | `PhotoGallery`'s Menu-tab gate is an explicit `primaryCategories.includes("restaurant")` check, covered by a dedicated test case in `photo-gallery.test.tsx` |

</threat_model>
