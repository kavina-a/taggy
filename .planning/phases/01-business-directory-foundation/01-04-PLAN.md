## Phase Goal

**As a** Colombo consumer, **I want to** browse a real, structured directory of local
businesses — with categories, hours, address, attributes, and photos — **so that** I can
find and learn about a business before visiting or contacting it.

<objective>

production-grade idempotency (atomic transaction, fail-fast validation, slug-collision
detection), and finish the directory index to match UI-SPEC's category-grouped, paginated
layout.

requires, browsable through the full UI-SPEC-compliant index built here.

Output: a 100-300-row `businesses.json`, a transactional/idempotent `seed.ts`, and a
category-grouped, paginated `/directory` page.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer-curated 100-300-row seed file -> Postgres (single transaction) | Same write path as earlier plans, now at full data volume and wrapped in a transaction |
| `?page=` query param -> directory query | The only client-influenceable input in this phase's read path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | A malformed record partway through the now-100-300-row seed file corrupting the DB into a half-seeded state | high | mitigate | `prisma.$transaction` wraps the entire seed run; all validation (schema + per-category attributes + slug-uniqueness) happens in a pre-write pass before any `upsert` call, so a bad record fails the whole run atomically rather than partially writing |
| T-04-02 | Denial of Service | Directory index query growing unbounded as the dataset scales past 100+ rows | medium | mitigate | Server-side fixed page size (`take`), client only controls `page` number via `?page=`, never `take`/`limit` directly |
| T-04-03 | Tampering | Duplicate business slugs from manual curation silently overwriting the wrong record via upsert | medium | mitigate | Seed script's pre-write pass builds a `Set` of slugs and throws immediately on any collision, before the transaction opens |
| T-04-04 | Information Disclosure | `?page=` accepting a non-numeric or out-of-range value | low | accept | Next.js `searchParams` value is parsed with a safe integer parse and clamped to `>= 1`; an invalid value falls back to page 1 rather than throwing a raw error to the client — low severity since no sensitive data is gated by pagination |

</threat_model>
