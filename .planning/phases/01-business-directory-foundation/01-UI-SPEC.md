# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase ships only a browsable directory index and a business profile
page (LIST-01..06, LOC-02). No search/filter UI (Phase 2), no auth/account UI (Phase 2),
no review/vote/Q&A UI (Phase 3-5), no upload UI (Phase 5). Every contract element below is
scoped to those two screens only.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g. between category chip icon and label) |
| sm | 8px | Compact element spacing (hours row internal gap, chip padding) |
| md | 16px | Default element spacing (card padding, form/field gaps) |
| lg | 24px | Section padding (between business page sections: header, hours, attributes, gallery, menu) |
| xl | 32px | Layout gaps (page gutters on tablet+) |
| 2xl | 48px | Major section breaks (between page header and body content) |
| 3xl | 64px | Page-level spacing (top-level vertical rhythm on desktop) |

Exceptions:
- **44px minimum tap target** on all interactive elements (hours accordion toggle, tab
  buttons, photo gallery thumbnails, directory card whole-card tap area, "Get Directions"
  button). Non-negotiable for this product: target users are Sri Lankan consumers browsing
  on likely 3G/4G mobile connections, often outside Colombo on lower-end Android devices.
  Where the 8-point scale would produce a target smaller than 44px (e.g. a 32px icon-only
  button), pad to 44px with transparent hit-area, not by inflating the visible icon.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.5 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage mapping (so the executor never has to guess):
- **Display (28/600):** Business name (H1 on profile page); directory index page title.
- **Heading (20/600):** Section headings within a business page — "Hours", "Photos",
  "Menu", "About"/description heading, category group headings on the directory index.
- **Body (16/400):** Description text, address text, hours rows, attribute list items.
- **Label (14/400):** Category chip text, "Open now"/"Closed" badge text, photo count
  caption, breadcrumb text, metadata (e.g. "12 photos").

Only 4 sizes, 2 weights, per contract. Do not introduce a 12px or bold(700) anywhere in
this phase.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (business page) | "Get Directions" (opens map app / shows lat+lng pin — this phase's map pin is a core success criterion; no reviews/booking CTA exists yet) |
| Secondary CTA (directory index card) | "View profile" (whole card is tappable; label only shown if a card also needs an explicit affordance, e.g. on desktop hover state) |
| Empty state — photo gallery | Heading: "No photos yet" / Body: "Photos for this business haven't been added yet. Check back soon." |
| Empty state — menu tab (restaurants only) | Heading: "Menu not available yet" / Body: "This restaurant hasn't added menu photos yet." |
| Empty state — directory index (should not occur post-seed, but must exist for a bad category filter link) | Heading: "No businesses found" / Body: "There aren't any listings in this category yet. Browse all businesses instead." |
| Error state — business not found (bad/stale URL) | Heading: "We couldn't find that business" / Body: "It may have been removed or the link is incorrect. Browse the directory instead." + link back to directory index |
| Error state — image failed to load | Inline fallback: a neutral placeholder tile with a small "Image unavailable" label — never a broken-image icon, since 3G/4G drops are expected, not exceptional, for this audience |
| Destructive confirmation | None in Phase 1. There is no user-authored content, no accounts, and no delete/edit action anywhere in this phase's scope (reviews, photos-by-users, claims, and reports all arrive in later phases). Do not build a confirmation-dialog pattern yet. |

## Screens In Scope

Only these two screens exist in Phase 1 (no search, no auth, no reviews):

1. **Directory index** — a simple browsable list/grid of seeded businesses, grouped by
   top-level category (per LIST-05 taxonomy) with pagination or infinite scroll. This is
   the minimal navigation surface needed to reach a business page before Phase 2's
   search/filter/sort exists. Each card shows: photo (or placeholder), name, primary
   category, district (from LOC-02 address model). No rating, price, or distance yet —
   those depend on Phase 2/3 data.
2. **Business profile page** — name, categories (primary + secondary), description,
   address (district/DS-division + free text + map pin), 7-day hours with live open/closed
   state, category-conditional attributes, photo gallery, and (restaurants only) a pinned
   Menu tab of photos.

Do not design or scaffold: search bar, filters, sort controls, login/signup, review
composer, Q&A, photo upload, save/collections, or owner-response UI. All are out of this
phase's boundary per CONTEXT.md.

**Focal point per screen:**
- Directory index: the category-grouped card grid is the focal point — the eye should land
  on the first card's photo, not the page chrome.
- Business profile page: the hero photo + business name (Display, 28/600) together form the
  focal point at the top of the page; everything else (hours, attributes, gallery, menu) is
  secondary and ordered below it.

**Icon-only controls:** every icon-only interactive element (hours accordion chevron, tab
icons if used, breadcrumb separators that double as links) MUST carry an `aria-label` or
visually-hidden text fallback describing its action/destination — never ship an icon button
with no accessible name, since lucide-react icons carry no implicit label.

## Mobile & Performance Notes

Non-negotiable given the target audience (Sri Lankan consumers, likely 3G/4G, often
outside Colombo on lower-end Android hardware):

- **Mobile-first responsive layout** — design and build the single-column mobile layout
  first, then expand to tablet/desktop breakpoints, not the reverse.
- **Image handling:** lazy-load all gallery/menu photos below the fold; serve responsive
  `srcset`/`sizes` via Next.js `<Image>`; use a low-quality blur placeholder while loading,
  never a spinner-only state, for the hero/cover photo.
- **Hours accordion collapsed by default on mobile** to avoid pushing the photo gallery
  and menu tab below an unreasonable scroll depth on small screens.
- **44px minimum tap targets** everywhere (see Spacing Scale exception above).
