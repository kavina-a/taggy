## Phase Goal

**As a** Colombo consumer, **I want to** browse a real, structured directory of local
businesses — with categories, hours, address, attributes, and photos — **so that** I can
find and learn about a business before visiting or contacting it.

<objective>
Deliver LIST-02 as a complete vertical slice: a visitor can see a business's structured
7-day hours (with split shifts and holiday overrides) and a live, correctly-computed
"Open now"/"Closed" badge on the business page built in 01-01. RESEARCH.md flags the
overnight-hours + holiday-override interaction as this phase's one genuine domain-complexity
pitfall, so the core algorithm is written test-first.

Purpose: prove the hours model and open-now algorithm are correct on the two hardest cases
(midnight-crossing shifts, holiday overrides) before any UI is built on top of it.

Output: `computeOpenNow`, a passing test suite covering the pitfall cases, and a wired
hours accordion + status badge on the live business page.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server (Next.js Server Component) -> client badge | The open/closed value must be computed authoritatively on the server; the client only ever displays a value it's given |
| Developer-curated hours/override rows -> Postgres | Same seed-script write path as 01-01, still validated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | Malformed `hours`/`hoursOverrides` rows (e.g. non-"HH:mm" time strings, out-of-range dayOfWeek) reaching the DB via the seed script | high | mitigate | `hoursRowSchema`/`hoursOverrideRowSchema` (Zod, regex-validated `HH:mm`, bounded `dayOfWeek`) validate every row before the seed script's upsert; `@@unique([businessId, date])` on `BusinessHoursOverride` prevents duplicate overrides for the same date at the DB level |
| T-02-02 | Tampering | Client-side timezone spoofing affecting the displayed open/closed state | medium | mitigate | `computeOpenNow` always runs server-side with a hardcoded `Asia/Colombo` zone constant; the client component only renders the boolean it receives as a prop, never recomputes it from `new Date()` |
| T-02-03 | Repudiation | No audit trail of who/when changed a business's hours | low | accept | No write UI exists yet in this phase — hours are only set by the developer-run seed script, not by any user-facing mutation; audit logging becomes relevant once Phase 4+ introduces owner-editable data |

</threat_model>
